# Phase 2 authentication contract

Only passenger self-registration is public. The seed creates Jashim as DRIVER, and Nusrat, Rafiq and Shirin as PASSENGER. Seed email addresses and instructions appear in README; their password comes only from `AUTH_DEMO_PASSWORD` in the local `.env`. The seed is idempotent and never resets existing passwords or changes existing roles.

`argon2` hashes each password using Argon2id, 19 MiB memory (`memoryCost: 19456` KiB), 2 iterations and parallelism 1, with per-password salt from the library. Password length is 12–128 characters. Registration normalizes email with trim/lowercase, forces PASSENGER, rejects additional fields, and writes user and first session in **one SQL statement** so a failed session insert cannot leave a registered-but-unsigned-in account. Incorrect and unknown logins share the same 401 response. Driver signup is not exposed.

Sessions are 32 random bytes encoded as base64url. The browser receives a `dtp_session` cookie with `HttpOnly`, `SameSite=Lax`, `Path=/`, a seven-day max age, and `Secure` in production. It has no Domain attribute. PostgreSQL stores only a SHA-256 digest of the random session token and checks expiry/revocation on every authenticated request. Logout sets `revoked_at` and clears the cookie. Successful login replaces an existing browser cookie and revokes its previous token; a new session has its own expiry. Production startup requires an HTTPS `APP_ORIGIN`.

For cookie-changing auth POSTs, require exact `Origin` from `APP_ORIGIN` and `application/json`; local Vite origin 5173 is additionally allowed only outside production. These rules work with the same-origin web `/api` proxy, `SameSite=Lax`, and HttpOnly cookie; they are a minimal CSRF-conscious policy, not permission to turn on wildcard credentialed CORS. Nginx replaces the forwarded client IP header; Express trusts one proxy hop. Registration and login have a bounded, process-local 15-minute throttle (registration 10/IP; login 30/IP and 5/IP+normalized email). Error codes include `INVALID_INPUT`, `INVALID_CREDENTIALS`, `AUTH_REQUIRED`, `EMAIL_IN_USE`, `RATE_LIMITED`, `ORIGIN_NOT_ALLOWED`, `UNSUPPORTED_MEDIA_TYPE`, `FORBIDDEN`. The process-local throttle is a documented MVP limitation if scaling across instances.

`requireSession` loads the user by hashed token; `requireRole('PASSENGER'|'DRIVER')` checks its authenticated role. Future ride/driver endpoints must compose these guards with resource ownership checks. The API returns only `{ id, name, email, role }` for an authenticated user; passwords, password hashes, session hashes and raw session tokens do not appear in JSON or structured logs. Auth logs include safe actor ID, route, status, error code, request ID and duration; request bodies, cookie headers and secrets are excluded.
